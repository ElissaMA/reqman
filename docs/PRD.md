# 定检需求单管理系统 产品需求文档 (PRD)

**版本**: V3.0  
**更新日期**: 2026-07-25  
**项目名称**: 定检需求单管理系统 (Inspection Demand Management System)

---

## 1. 产品概述

### 1.1 产品定位

定检需求单管理系统是一款面向航空维修领域的桌面端Web应用，用于管理飞机定检（Scheduled Maintenance）过程中的工卡、工具、航材需求，支持从工作清单Excel文件导入、自动匹配工卡数据库、生成标准化定检需求单Excel文件。

### 1.2 核心价值

- **效率提升**：自动化匹配工卡与工具/航材，减少人工查找和比对时间
- **数据标准化**：统一管理工卡信息、飞机信息、工卡组，确保数据一致性
- **流程规范化**：从工作清单上传到需求单生成，形成完整的工作闭环
- **操作可追溯**：所有数据变更自动记录操作日志，支持审计追溯

### 1.3 目标用户

- 航空维修工程师
- 定检计划员
- 航材管理人员
- 维修管理人员

## 2. 功能模块

### 2.1 工卡管理 (Card Management)

**功能描述**：管理飞机定检工卡的基本信息、工具需求和航材需求。

| 功能 | 描述 | 路由 |
|------|------|------|
| 工卡列表 | 支持搜索（编码/名称）、分类筛选、排序 | `/card/list` |
| 新增工卡 | 填写工卡编码、名称、分类、任务类型，添加工具/航材 | `/card/new` |
| 编辑工卡 | 修改工卡信息，更新工具/航材配置 | `/card/<id>/edit` |
| 删除工卡 | 删除工卡记录 | `/card/<id>/delete` |
| 工卡详情 | 查看工卡完整信息（AJAX） | `/card/<id>` |

**工卡数据字段**：
- 工卡编码（唯一索引）
- 工卡名称
- 分类（发动机/机体/电子/特检/支援）
- 任务类型（A/EO分段/DP项目/20MO/24MO）
- 工具列表（设备名称、件号、数量、使用类型、备注）
- 航材列表（材料名称、件号、数量、使用类型、备注）
- 工具确认状态（确认无工具）
- 航材确认状态（确认无航材）
- 所属工卡组

### 2.2 工卡组管理 (Card Set Management)

**功能描述**：将多个工卡组织为工卡组，配置共享工具/航材，自动同步到所有成员工卡。

| 功能 | 描述 | 路由 |
|------|------|------|
| 工卡组列表 | 显示工卡组及成员数量 | `/card/sets` |
| 新增工卡组 | 选择工卡、配置共享工具/航材 | `/card/sets/new` |
| 编辑工卡组 | 修改成员工卡、更新共享资源 | `/card/sets/<id>/edit` |
| 删除工卡组 | 删除工卡组，解绑成员工卡 | `/card/sets/<id>/delete` |

**核心逻辑**：
- 工具/航材在工卡组级别定义，自动同步到所有成员工卡
- 编辑工卡组时重新同步所有成员
- 删除工卡组时解绑所有成员工卡

### 2.3 飞机信息管理 (Aircraft Management)

**功能描述**：管理飞机基本信息，用于定检需求单的生成。

| 功能 | 描述 | 路由 |
|------|------|------|
| 飞机列表 | 显示所有飞机信息 | `/card/aircraft` |
| 新增飞机 | 填写注册号、机型、发动机等信息 | `/card/aircraft/new` |
| 编辑飞机 | 修改飞机信息（注册号只读） | `/card/aircraft/<id>/edit` |
| 删除飞机 | 删除飞机记录 | `/card/aircraft/<id>/delete` |

**飞机数据字段**：
- 注册号（唯一）
- 机型
- 发动机型号
- 机队序列号 (FSN)
- 制造商序列号 (MSN)
- APU型号

### 2.4 工作包管理 (Work Package Management)

**功能描述**：上传工作清单Excel文件，解析工卡信息，创建工作包，支持自动匹配和状态管理。

| 功能 | 描述 | 路由 |
|------|------|------|
| 上传工作清单 | 上传日常/其他Excel文件 | `/upload` (POST) |
| 工作包列表 | 显示已上传的工作包，按日期状态着色 | `/upload` (GET) |
| 重新匹配 | 重新匹配工作包与工卡数据库 | `/packages/<id>/rematch` |

**工作包状态**：
- 正常：未过期
- 警告（红色）：4天内到期
- 危险（灰色）：已过期1-2天
- 过期（自动删除）：超过2天

**Excel解析规则**：
- 数据起始行：第7行
- 列映射：B=工卡编码, E=任务类型, F=分类, H=工卡名称, L=备注
- 飞机信息：B2=注册号, D2=机型, H2=描述, J2=工作包
- 日期：C4单元格
- 文件限制：10MB，最多5000行

### 2.5 定检需求单生成 (Demand Sheet Generation)

**功能描述**：预览匹配结果，生成标准化定检需求单Excel文件。

| 功能 | 描述 | 路由 |
|------|------|------|
| 预览需求单 | 显示匹配的工具/航材/新工卡 | `/generate` (GET) |
| 生成需求单 | 下载Excel定检需求单 | `/generate` (POST) |

**预览内容**：
1. 基本信息（注册号、机型、日期、描述）
2. 使用条件（9项维护条件）
3. 工具预览（按分类分组）
4. 航材预览（按分类分组）
5. 新增/未配置工卡（支持编辑/新增）
6. 备件预览

**Excel生成规则**：
- 标题行：定检需求单（B-{注册号} {描述}）{日期}
- 使用条件表：9行维护条件
- 工具表：按分类分组，每类最少3行
- 新增工作行：红色高亮
- 航材表：每类最少3行
- 备件表：最少2行

**匹配逻辑**：
- 已匹配：数据库存在且工具/航材已配置
- 新增：数据库存在但未配置，或不存在于数据库
- 已撤销：备注包含"撤销"
- 工卡组去重：同一工卡组的工具/航材只输出一次

### 2.6 操作日志 (Operation Logs)

**功能描述**：记录所有数据变更操作，支持筛选、分页、删除。

| 功能 | 描述 | 路由 |
|------|------|------|
| 日志列表 | 分页显示，支持多条件筛选 | `/card/logs` |
| 删除日志 | 批量删除选中日志 | `/card/logs/delete` |

**筛选条件**：
- 操作类型（新增/修改/删除）
- 目标类型（工卡/工卡组/飞机信息）
- 关键词（目标标识/名称）
- 提交日期

**日志配置**：
- 每页显示：20条
- 最大保留：200条（启动时自动裁剪）

## 3. 数据模型

### 3.1 存储方案

- **存储方式**：单文件JSON (`data/reqman_db.json`)
- **写入策略**：原子写入（先写临时文件再rename）
- **备份机制**：每次写入自动备份 `.bak` 文件
- **自愈能力**：启动时检测主文件损坏，自动从备份恢复
- **索引优化**：工卡编码倒排索引，O(1)查找

### 3.2 实体关系

```
┌─────────────┐       ┌─────────────┐
│   Aircraft   │       │   CardSet    │
│  (飞机信息)  │       │  (工卡组)    │
└─────────────┘       └─────────────┘
                            │
                            │ 1:N
                            ▼
┌─────────────┐       ┌─────────────┐
│     Card     │◄──────│   CardSet    │
│   (工卡)    │ set_id│  (工卡组)    │

       │
       │ 1:N
       ▼
┌─────────────┐
│ WorkPackage │

└─────────────┘
```

## 4. 用户工作流

### 4.1 主流程：生成定检需求单

```
┌─────────────────────────────────────────────────────────────┐
│  1. 上传工作清单                                              │
│     /upload → 上传日常/其他Excel文件                          │
│     → 解析工卡列表、飞机信息                                   │
│     → 创建工作包（is_matched=false）                          │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  2. 匹配工卡数据库                                            │
│     首次访问/generate时自动触发                                │
│     → 按工卡编码匹配数据库                                    │
│     → 已配置 → matched                                        │
│     → 未配置/不存在 → new                                      │
│     → 备注含"撤销" → cancelled                                │
│     → 工卡组工具/航材同步                                      │
│     → 按工卡组去重                                            │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  3. 预览与完善                                                │
│     /generate → 显示匹配结果                                  │
│     → 工具预览（按分类分组）                                   │
│     → 航材预览（按分类分组）                                   │
│     → 新增工卡（支持编辑/新增）                                │
│     → 备件预览                                                │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  4. 补充缺失数据（如需要）                                    │
│     点击"新增工卡"或"编辑工卡"                                │
│     → /card/new?task_code=...（预填信息）                     │
│     → 添加工具/航材 → 保存                                    │
│     → localStorage记录已处理工卡                              │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  5. 生成Excel                                                │
│     /generate (POST)                                         │
│     → 填写表头（注册号/日期/描述）                             │
│     → 写入9行使用条件                                         │
│     → 写入工具表（按分类分组）                                 │
│     → 写入新增工作行（红色高亮）                               │
│     → 写入航材表                                              │
│     → 写入备件表                                              │
│     → 下载：定检需求单（B-{注册号} {描述}）{日期}.xlsx          │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 工卡管理流程

```
浏览工卡列表 → 搜索/筛选 → 点击查看详情
    │
    ├─→ 新增工卡 → 填写信息 → 添加工具/航材 → 保存
    │
    ├─→ 编辑工卡 → 修改信息 → 更新工具/航材 → 保存
    │
    └─→ 删除工卡 → 确认 → 删除
```

### 4.3 工卡组管理流程

```
浏览工卡组列表 → 点击查看详情
    │
    ├─→ 新增工卡组 → 命名 → 选择工卡 → 配置共享工具/航材 → 保存
    │                         └─→ 自动同步到所有成员工卡
    │
    ├─→ 编辑工卡组 → 修改成员/资源 → 保存
    │                         └─→ 重新同步所有成员
    │
    └─→ 删除工卡组 → 确认 → 删除 → 解绑所有成员
```

## 5. 技术架构

### 5.1 技术栈

| 层级 | 技术 |
|------|------|
| 后端框架 | Flask 3.1+ |
| 模板引擎 | Jinja2 |
| 前端UI | Bootstrap 5.3.3 |
| Excel处理 | openpyxl |
| 数据存储 | JSON文件（原子写入+自动备份） |
| 配置管理 | python-dotenv |
| 测试框架 | pytest |

### 5.2 架构模式

- **应用工厂模式**：`create_app()` 统一初始化
- **蓝图模式**：按功能模块拆分路由
- **服务层模式**：`CardService` 封装业务逻辑
- **依赖注入**：通过 `app.extensions` 注入服务实例

### 5.4 API设计

**响应格式**：
```json
{
  "success": true,
  "data": {},
  "message": "操作成功",
  "error_code": null
}
```

**双模式响应**：
- AJAX请求：返回JSON
- 表单请求：flash() + redirect()

### 5.5 性能优化

- 工卡编码倒排索引：O(1)查找
- 线程锁保护ID生成
- 懒加载匹配：首次访问预览页时触发
- 工卡组去重：同一工卡组工具/航材只输出一次
- 请求日志中间件：记录耗时，标记慢请求（>2s）
