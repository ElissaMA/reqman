# Excel 模板格式一致性与数据日志规范综合修复方案

## 1. 总原则

1. 模板是固定文字、合并、字体、边框、填充、对齐、行高和打印范围的权威来源。
2. 生成器只写入明确的动态单元格，不清空或重建整段模板。
3. 动态行超过预留范围时，复制模板样式并同步维护合并、行高和打印范围。
4. 模板结构异常时明确报错，不静默清空、重建或丢弃内容。
5. 手动备用航材填写功能已弃用，备用航材只从数据库导出。
6. 特检/支援专业按当前业务范围忽略，不扩展现有三专业模板。
7. 测试使用隔离模板和隔离数据库，不修改真实业务数据。

## 1A. 数据与日志规范（2026-09-10 新增，已确认规则）

### 规则

1. **日志与"新建/编辑时间"只记录人工行为**。AMRO 版本检查等自动批量刷新不写操作日志、不刷新 `log_time`；编写日期变化以改版清单输出为权威记录。
2. **`MAX_LOGS` 保持 500 条**不变。日志噪音源消除后，500 条滚动窗口足以覆盖近期人工行为；历史被挤掉的条目不回填伪造。
3. **`sync_set_to_cards` 属人工操作链**：工卡组保存后同步组内工卡，组内卡刷新 `log_time`，并只记 1 条汇总日志，不逐卡刷屏。
4. 旧数据（无 `log_time` 的历史工卡/工卡组）不回填伪造时间，显示 `—` 排最后，编辑一次后自然刷新。

### 已确认的问题与根因

- 工卡组列表不显示"新建/编辑日期"、排序失效：`set_routes.py` 组装列表 dict 时丢弃了存储层已有的 `log_time` 字段；`sets.html` 还缺少载入自动排序（工卡列表页有）。
- 工卡日志缺少"新建"条目：日志滚动窗口被自动噪音占满——AMRO 版本检查对每张日期变化卡调 `bulk_update` 写 1 条 update 日志，实测 500 条日志中 455 条 changes 仅含 write_date，纯自动刷新把人工 add 条目挤出保留窗口。

### 实施内容（待执行）

1. `set_routes.py`：列表 dict 补 `"log_time": set.get("log_time", "")`，恢复时间显示与服务端倒序。
2. `sets.html`：DOMContentLoaded 增加 `AppFilter.sort(document.getElementById('setTable'), 6)` 默认倒序，与工卡列表一致。
3. `card_store.py`：`bulk_update` 增加语义参数 `log=True, touch=True`——`log=False` 不写日志、跳过 `_detect_changes`；`touch=False` 不刷新 `card["log_time"]`（工卡号索引维护照常执行）；默认行为不变，现有调用方不受影响。
4. `versions.py`：两处版本检查 `bulk_update` 调用改传 `log=False, touch=False`。
5. `card_store.py`：`sync_set_to_cards` 同步后刷组内卡 `log_time` 并写 1 条汇总日志（identifier=首卡工卡号+` 等N张（工卡组同步）`）；**组内无卡（N=0）时跳过刷时间与汇总日志**；汇总日志 changes 携带同步字段摘要，保证日志页可考证。

### 可行性审查补充结论（2026-09-10 二次核查）

1. **必改现有测试**：`tests/test_amro_version.py:57-58` 断言版本检查后日志含 write_date 变更，与 `log=False` 直接冲突，实施时须按新语义改写（断言无新日志、log_time 不变）。
2. **作废卡 delete 日志**：版本检查中 `_move_to_cancelled` → `store.delete` 仍对每张作废卡写 1 条 delete 日志，属自动行为残留噪声（量级小）。按规则 1 应同样视为自动行为——实施时需明确给 `delete` 增加静默参数或接受现状。
3. **sets.html 既有死筛选**：名称/专业/提醒类型三个筛选框缺 `data-col`（仅日期筛选生效），属既有缺陷；本轮改 sets.html 时顺带补上，避免与新增自动排序 e2e 冲突。
4. **可感知 UI 变化**：工卡组保存后成员卡 `log_time` 刷新，会使工卡列表（默认按时间倒序）成员卡集体置顶——语义符合"人工行为"规则，验收时知会即可。
5. **版本日志 API 语义变化**：`/packages/amro-version-logs`（`get_version_logs` 筛 write_date 变更）在 `log=False` 后只剩人工编辑记录；该页面区块已移除、仅保留 API，影响低，不算回归。

### 测试

- 集成：sets 列表含 `log_time` 且倒序；`bulk_update(log=False, touch=False)` 更新字段但无新日志、`log_time` 不变；`sync_set_to_cards` 恰 1 条汇总日志（N>0）且组内卡时间刷新，N=0 无汇总日志；改写 `test_amro_version.py` 旧断言。
- e2e：工卡组页面时间列显示与默认倒序（并入现有 e2e 套件回归）。

### 与模板修复的衔接

- 阶段 1（需求单）新增用例：版本检查批量刷新 write_date 后，工卡 `log_time` 与日志条数均不变（自动行为不冒充人工编辑）。
- 阶段 4 公共能力：`bulk_update` 的 `log/touch` 语义参数写入公共数据访问规范，后续任何批量自动刷新调用必须显式声明语义。

## 2. 当前审计结论

### 2.1 需求单模板

文件：`assets/demand_template.xlsx`，工作表：`需求单`。

已确认的问题：

- `A1` 模板标题是“定检中队定检需求单……”，但 `form_generator.py` 硬编码写成“机务二队定检需求单……”。

- 模板第 15 行以后由维护人员增加的固定文字、字体、边框、填充、合并和 I 列内容可能丢失。
- 模板实际使用到第 42 行，但打印范围固定到第 41 行。
- 动态数据区样式没有完整继承模板，区首尾边框、字号和对齐可能发生变化。

### 2.5 库存输出

库存输出不是独立静态模板，而是对需求单文件的副本进行库存回填。它只修改库存列和对应颜色，会继承上游需求单的标题和格式问题。

### 2.6 库存回填读取侧（二次审查补充，高风险）

`xlsx_workbook.py:67-106` `read_demand` 的定位方式存在静默丢数据风险：

- 按 `wb.active` 而非 sheet 名"需求单"定位——用户上传的副本若激活了别的 sheet 会读错表。
- 航材区靠固定关键字 `定检专业\n（航材）`、备用区靠 `备用航材需求` 子串在 A 列定位：用户改动模板固定文字后，最坏情况是**备用区整段静默不回填**（航材区照常查询，摘要"成功 X 件号"看似正常），或整体报"需求单中未找到航材件号"（文案误导，真实原因是模板标题被改）。
- 区边界依赖 `^[三四五六七八九十]、` 中文编号正则——维护者调整编号（"1."/去编号）后边界失效，最坏航材区读取吞并备用区。

### 2.7 需求单信息区与表头来源（二次审查补充，中高风险）

- `_fill_conditions`（`form_generator.py:191-198`）无条件覆盖模板 4-12 行 C/D/G 默认文字：表单留空提交时模板默认文案被 `""` 写平；且这段固定文字存在**三份拷贝**（模板 / `generate/form.html:29` 预填 / `config.py` CONDITIONS），模板改文案后预填不跟随。
- `_fill_header`（`:164-188`）除 A1 文字外，还把行 1-3 的字体、边框、对齐全部用代码重建——模板改字号/边框即丢。
- `A24`/`B24`"本次定检新增工作"、行 25 航材表头 9 列、行 36 备用表头 9 列、"（暂无）"占位均硬编码重写（当前与模板巧合一致，来源错误）。
- 动态区起始行全部依赖固定行号（15/24/25/35，提醒单 `DATA_START=7`）：模板条件区增删一行，下游整体静默错位（工具区会写进条件区）。

### 2.8 报错体验与提醒单标签（二次审查补充）

- 借用清单模板结构异常（`checklist_generator.py:93` `_zone_bounds` 抛 RuntimeError）在三个下载路由无 catch → 落入全局兜底 500，用户改了区标签（如"通用"→"通用工具"）得到的是与代码 bug 无法区分的 500。
- 提醒单 B2 模板原文"定检级别："被代码改写为"定检描述：…"（与需求单 A1 同类问题），`tests/integration/test_reminder_api.py:68` 锁死旧行为，阶段 3 改造时必须同步改写。
- `error_handlers.py:16` 已有 `ValidationError` 全局 handler（flash + 400/JSON），模板契约报错可直接复用该模式。

### 2.9 模板格式修复与输出稳定性建议

五个模板的格式修复清单，目标：**输出文件更稳定、生成更快、内容准确**。

| 模板 | 格式修复要点 |
|---|---|
| 需求单 | 固定区（A1/A2/A13/A35、行 1-3 样式、表头行 14/25/36、A24/B24）全部模板驱动；动态区只写白名单单元格；动态行复制参考行样式；扩行平移合并/行高/print_area |
| 工具清单 | 空行整行 B:G 判断；保留区首尾 medium 边框与模板字号；扩行复制内部数据行样式；A1 只回填有来源字段（飞机/日期），无来源不伪造 |
| 航化清单 | 同上（B:H）；保留模板 12pt/Arial10 字号差异；A25:F32 警戒耗材区纳入契约保护 |
| 提醒单 | 数据行继承模板字体属性；按换行数设最小行高；打印区按实际末行；B2 标签模板驱动 |
| 改版清单 | 三行富文本设行高；超 4996 行复制样式或明确报错；A1 长标题行高；打印区 |

稳定性与性能措施：

1. **模板契约校验 fail-fast**：sheet 名、固定单元格、合并范围、动态白名单、容量在生成入口统一校验，异常即明确报错——杜绝静默错位与静默丢数据。
2. **公共 helper**：样式复制（字体/边框/填充/对齐/行高）与动态扩行（复用 `checklist_generator._extend_zone` 的 unmerge→insert→复制样式→re-merge 模式）收敛为公共能力。
3. **减少写放大**：生成器不再重设整行样式，只写白名单单元格——既保格式又提速。
4. **缓存保持**：`load_template` 按 mtime 缓存的机制保留，用户改模板即时生效。
5. **快照测试防回归**：阶段 0 起每个模板建立固定文字/合并/边框/行高/打印区快照，任何生成器改动由测试兜底。

### 2.10 低风险记录（单独处理/测试护栏）

- `read_demand` 的 `data_only=True`：E 列数量为公式且无缓存值时 qty=0 → 标红判定失真。
- 库存副本标红/标黄整行覆盖 B..G 填充会抹掉原底色；openpyxl load→save 往返对文本框/形状/复杂图表可能丢失。
- `_extend_zone` 只平移下方合并区，区内存在 A 标签以外内部合并会被破坏（当前模板无）——契约测试断言"四区内无内部合并"。
- 航化模板 `A25:A32`、`F25:H31` 合并区代码未认识，需纳入契约盘点。
- `build/lib/.../form_generator.py` 残留旧版"机务二队"硬编码（阶段 4 清理确认）。

## 3. 阶段 0：建立模板契约和基线

### 目标

把五个模板的固定区、动态区、可扩展区、样式行和打印范围固化为可测试契约。

### 实施内容

- 记录每个模板的 sheet 名、固定标题坐标、动态列范围、预印行、合并区、样式参考行、容量和打印范围。
- 需求单单独记录 A1、A2、A13、A35、工具区、航材区、备用区、H 列合并和 I 列独立确认栏。
- 建立动态写入单元格白名单；白名单外的值、样式和合并不允许被生成器修改。
- 用隔离模板建立空数据、少量数据、区满和超容量基线输出。
- 添加固定文本、合并、边框、字体、对齐、行高和打印范围快照测试。

### 验收标准

- 能检测生成器是否写入模板固定区。
- 模板标题或固定文案被人为修改后，测试能确认输出是否保留修改。
- 每个动态区都有明确的可写范围和扩展规则。

## 4. 阶段 1：修复需求单生成

### 目标

停止覆盖模板固定内容，保证需求单值、结构、样式和打印结果与模板一致。

### 实施内容

#### 4.1 标题模板驱动

- `A1` 读取模板原文，只替换明确的日期、注册号和工作包描述占位符。
- 不再硬编码“机务二队”。
- `A35` 保留模板标题，不再无条件写入固定队名。
- 需求单标题、备用标题和其它固定文案只保留模板一个来源。

#### 4.1A 行 1-3 样式与表头来源（二次审查补充）

- `_fill_header` 不再重建行 1-3 的字体/边框/对齐，只替换 A1 动态占位符（M1）。
- `A24`/`B24`、行 25 航材表头、行 36 备用表头、"（暂无）"占位列入阶段 0 白名单，文字来自模板、代码只写动态数据（M2）。
- C/D/G 条件单元格明确列入动态白名单（表单值覆盖是设计行为），但预填默认值收敛为服务端下发单一来源：`generate/form.html` 的预填值改由后端从 config/模板下发，消除三份拷贝漂移（H3）。

#### 4.2 停止整体清空

- 删除从第 15 行到末尾的整体 unmerge、清值、清字体、清边框和清填充逻辑。
- 只清理本次输出需要写入的动态数据单元格。
- 保留模板固定文字、合并结构、I 列确认栏和用户维护的固定格式。
- 模板中的“发动机工具/机体工具/电子工具”等固定标签不再被代码缩写覆盖。

#### 4.3 动态行和样式

- 动态行复制模板相应参考行的字体、边框、填充、对齐、数字格式、保护属性和行高。
- 需求单动态扩行时同步平移下方合并区、行高和打印范围。
- 保留 H 列纵向合并和 I 列独立确认栏。
- 至少覆盖模板已有第 42 行；超出模板范围时继续扩展并继承样式。

#### 4.4 测试

- 修改模板 A1/A35 文案后，输出保留模板文案。
- 模板第 15 行以后增加固定文字、字体、边框、填充和合并后，输出不丢失。
- 输出包含第 42 行，动态扩展后打印范围覆盖新增行。
- I 列内容和独立样式不被清除或错误合并。
- 自动备用航材正常导出；不恢复手动备用航材输入。
- 行 1-3 样式、A24/B24、表头行、"（暂无）"来自模板（白名单快照断言）。
- `read_demand` 关键字场景纳入契约测试（与阶段 4 读取侧契约联动）。

## 5. 阶段 2：修复工具和开封航化清单

### 目标

只填安全的动态空行，完整继承工具模板和航化模板的原有格式。

### 实施内容

#### 5.1 空行占用判断

- 工具清单检查整行 B:G。
- 航化清单检查整行 B:H。
- B 为空但 C/D 或清点栏已有内容时，不覆盖；按项目约定记录可追踪提示或返回模板占用错误。
- 预印行保持只读。

#### 5.2 样式继承

- 删除动态写入时强制统一宋体 11、全细边框和统一对齐的逻辑。
- 直接使用模板空白行已有样式。
- 工具区首行/末行保留 medium 边框。
