# Excel 模板格式一致性分阶段修复方案

## 1. 总原则

1. 模板是固定文字、合并、字体、边框、填充、对齐、行高和打印范围的权威来源。
2. 生成器只写入明确的动态单元格，不清空或重建整段模板。
3. 动态行超过预留范围时，复制模板样式并同步维护合并、行高和打印范围。
4. 模板结构异常时明确报错，不静默清空、重建或丢弃内容。
5. 手动备用航材填写功能已弃用，备用航材只从数据库导出。
6. 特检/支援专业按当前业务范围忽略，不扩展现有三专业模板。
7. 测试使用隔离模板和隔离数据库，不修改真实业务数据。

## 2. 当前审计结论

### 2.1 需求单模板

文件：`assets/demand_template.xlsx`，工作表：`需求单`。

已确认的问题：

- `A1` 模板标题是“定检中队定检需求单……”，但 `form_generator.py` 硬编码写成“机务二队定检需求单……”。
- 备用航材标题 `A35` 同样可能被硬编码的“机务二队”覆盖。
- 生成器从第 15 行起解除合并、清空值并清除样式，再按代码重建工具、航材和备用区域。
- 模板第 15 行以后由维护人员增加的固定文字、字体、边框、填充、合并和 I 列内容可能丢失。
- 模板实际使用到第 42 行，但打印范围固定到第 41 行。
- 动态数据区样式没有完整继承模板，区首尾边框、字号和对齐可能发生变化。

不纳入本轮问题：手动备用航材功能已弃用；特检/支援内容按当前范围忽略。

### 2.2 工具借用清单与开封航化清单

文件：

- `assets/tools_template.xlsx`
- `assets/materials_template.xlsx`

已确认的问题：

- 动态写入时只检查 B 列是否为空，可能覆盖 B 为空但 C/D 或清点栏已有人工内容的行。
- 动态写入统一设置宋体 11、全细边框和统一对齐，可能破坏模板预设字号和区首尾边框。
- 工具模板专业区首行/末行的粗边框可能被改成细边框。
- A1 中的姓名、工号、飞机和日期占位不会自动回填；这属于内容完整性问题，不是合并或样式问题。
- 标题、表头、区标签和预印行目前可保留，但应增加回归测试。

### 2.3 提醒单模板

文件：`assets/reminder_template.xlsx`，工作表：`工卡提醒`。

已确认的边界：

- 标题、图例和专业表头在模板容量内基本保留。
- 数据行没有按长文本动态设置行高，长工卡名称可能被裁切。
- 超过第 5000 行后，新行不会自动继承模板样式。
- 模板未设置明确打印范围，可能把大量空白预格式行纳入打印。
- 特检/支援按当前三专业业务范围忽略。

### 2.4 改版清单模板

文件：`assets/check_template.xlsx`，工作表：`改版清单`。

已确认的边界：

- A1 会被代码动态写入工作包标签和检查日期，这是设计行为。
- 三行富文本数据没有显式行高，长文本可能在 Excel/WPS 或打印时被裁切。
- 超过第 4996 行后，新行不会继承模板绿底、边框和字体。
- 模板未设置明确打印范围，可能产生大量空白打印页。
- 特检/支援按当前三专业业务范围忽略。

### 2.5 库存输出

库存输出不是独立静态模板，而是对需求单文件的副本进行库存回填。它只修改库存列和对应颜色，会继承上游需求单的标题和格式问题。

## 3. 阶段 0：建立模板契约和基线

### 目标

把五个模板的固定区、动态区、可扩展区、样式行和打印范围固化为可测试契约。

### 实施内容

- 记录每个模板的 sheet 名、固定标题坐标、动态列范围、预印行、合并区、样式参考行、容量和打印范围。
- 需求单单独记录 A1、A2、A13、A35、工具区、航材区、备用区、H 列合并和 I 列独立确认栏。
- 建立动态写入单元格白名单；白名单外的值、样式和合并不允许被生成器修改。
- 用隔离模板建立空数据、少量数据、区满和超容量基线输出。
- 添加固定文本、合并、边框、字体、对齐、行高和打印范围快照测试。

### 验收标准

- 能检测生成器是否写入模板固定区。
- 模板标题或固定文案被人为修改后，测试能确认输出是否保留修改。
- 每个动态区都有明确的可写范围和扩展规则。

## 4. 阶段 1：修复需求单生成

### 目标

停止覆盖模板固定内容，保证需求单值、结构、样式和打印结果与模板一致。

### 实施内容

#### 4.1 标题模板驱动

- `A1` 读取模板原文，只替换明确的日期、注册号和工作包描述占位符。
- 不再硬编码“机务二队”。
- `A35` 保留模板标题，不再无条件写入固定队名。
- 需求单标题、备用标题和其它固定文案只保留模板一个来源。

#### 4.2 停止整体清空

- 删除从第 15 行到末尾的整体 unmerge、清值、清字体、清边框和清填充逻辑。
- 只清理本次输出需要写入的动态数据单元格。
- 保留模板固定文字、合并结构、I 列确认栏和用户维护的固定格式。
- 模板中的“发动机工具/机体工具/电子工具”等固定标签不再被代码缩写覆盖。

#### 4.3 动态行和样式

- 动态行复制模板相应参考行的字体、边框、填充、对齐、数字格式、保护属性和行高。
- 需求单动态扩行时同步平移下方合并区、行高和打印范围。
- 保留 H 列纵向合并和 I 列独立确认栏。
- 至少覆盖模板已有第 42 行；超出模板范围时继续扩展并继承样式。

#### 4.4 测试

- 修改模板 A1/A35 文案后，输出保留模板文案。
- 模板第 15 行以后增加固定文字、字体、边框、填充和合并后，输出不丢失。
- 输出包含第 42 行，动态扩展后打印范围覆盖新增行。
- I 列内容和独立样式不被清除或错误合并。
- 自动备用航材正常导出；不恢复手动备用航材输入。

## 5. 阶段 2：修复工具和开封航化清单

### 目标

只填安全的动态空行，完整继承工具模板和航化模板的原有格式。

### 实施内容

#### 5.1 空行占用判断

- 工具清单检查整行 B:G。
- 航化清单检查整行 B:H。
- B 为空但 C/D 或清点栏已有内容时，不覆盖；按项目约定记录可追踪提示或返回模板占用错误。
- 预印行保持只读。

#### 5.2 样式继承

- 删除动态写入时强制统一宋体 11、全细边框和统一对齐的逻辑。
- 直接使用模板空白行已有样式。
- 工具区首行/末行保留 medium 边框。
- 扩行时复制内部数据行样式，避免把区尾粗边框复制到区域内部。
- 航化行保留模板中的字号、边框、填充和对齐差异。

#### 5.3 标题和打印范围

- 保留模板标题、表头、区标签和预印项。
- 只有在存在可靠数据来源时回填 A1 中的飞机、日期等字段；没有姓名/工号来源时不伪造。
- 按实际最后数据行设置打印范围，避免空白页。
- 超容量时复制最后有效模板行样式，达到系统限制时明确报错。

### 测试

- B 为空但 C/D/E:G 或 E:H 有人工内容时，生成器不覆盖。
- 区首尾写入后比较字体、边框、填充、对齐和行高。
- 区满扩行后检查新增行样式和原区尾粗边框。
- A1、标题、预印行和合并区保持不变。
- 同件号合并、预印排除和数据库名称规范规则继续通过。

## 6. 阶段 3：修复提醒单和改版清单版式边界

### 6.1 提醒单

- 数据行继承模板字体属性，不覆盖粗体、下划线等自定义格式。
- 根据工卡号、名称和标记的换行数设置最小行高。
- 超过模板预置行时复制最后模板数据行的样式和行高。
- 设置实际打印范围，避免把 5000 行空白格式纳入打印。
- 超容量时明确报错。

### 6.2 改版清单

- 三行富文本写入后设置足够行高。
- A1 长标题按内容调整行高。
- 超过第 4996 行时复制最后数据行的绿底、边框、字体和对齐。
- 按实际最后输出行设置打印范围。
- 保留已有富文本颜色规则和三专业范围。

### 测试

- 长工卡名称和三行改版文本不裁切。
- 少量数据不会产生大量空白打印页。
- 容量边界新增行继承样式或明确报错。
- 模板标题和专业表头不被误改。

## 7. 阶段 4：公共模板输出能力和防回归

### 公共能力

- 样式复制 helper：字体、边框、填充、对齐、数字格式、保护属性和行高。
- 动态扩展 helper：插行、复制样式、平移合并、平移行高、更新打印范围。
- 模板契约校验 helper：sheet、固定单元格、合并范围、动态白名单和容量。
- 结构异常统一明确报错，不静默重建。

### 构建和部署一致性

- 确认运行路径使用 `src/reqman`，不从过时的 `build/lib` 导入。
- 重新构建或清理旧构建副本，避免生成器硬编码漂移。
- CI 增加旧组织名称硬编码检查和模板契约检查。

### 文档

记录以下维护规则：

- 哪些单元格是固定内容，哪些是动态内容。
- 哪些区域允许扩行。
- 模板维护人员可以修改哪些标题和固定文案。
- 手动备用航材已弃用。
- 特检/支援按当前业务范围忽略。

## 8. 阶段 5：验证和交付

### 验证顺序

1. 模板契约单测和真实模板隔离副本回归。
2. 需求单、提醒单、工具清单、开封航化清单、改版清单专项测试。
3. 下载接口和内容集成测试。
4. `ruff check src tests scripts`。
5. 全量非 e2e pytest。
6. 完整 e2e。
7. 代表性文件在 Excel/WPS/LibreOffice 中检查标题、合并、边框、长文本、打印范围和空白页。
8. `git diff --check`。

### 验收标准

- 需求单输出不再出现“机务二队”，模板自定义标题能反映到输出。
- 模板固定值、合并、字体、边框、填充、对齐和行高不被无故改变。
- 动态数据超出预留区时继续输出并继承模板格式。
- 工具和航化动态写入不覆盖人工内容，不破坏区首尾边框。
- 提醒单和改版清单长文本不被裁切，不产生大面积空白打印页。
- 手动备用航材不恢复，特检/支援不扩展。
- 单测、集成测试、e2e、ruff 和 diff 检查全部通过。

## 9. Git 与数据边界

- 所有实现继续在 `dev` 分支完成。
- 不修改真实数据库和运行态数据库；测试使用隔离副本。
- 用户手动修改的模板文件不回退、不覆盖，先纳入基线核对。
- 每个阶段完成后单独汇报测试结果。
- 提交、合并、推送分开执行，未经确认不执行后续 Git 操作。
